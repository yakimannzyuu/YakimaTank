# 0008. 設定アセットを正本にして、生成とワールドの更新を共通にする

- 状態：承認
- 日付：2026-11-13
- 関連：ADR 0001・0007、[SPEC_2026-11-13_セットアップと開発ワールド自動更新.md](../../02_Specifications/SPEC_2026-11-13_セットアップと開発ワールド自動更新.md)

## 背景

セットアップウィンドウで作る車両と、AI が検証する車両が同じものでないと、AI の検証が利用者の結果を保証しない。生成物を手で直すと、どの設定から作ったかが分からなくなる。Play 中に設定を試す方法は、試作で次のことが分かっている：数値の再適用（C 案）と、同じ構造の出し直し（A 案）は、`SetProgramVariable`（W2）で確実に動く。Play 中に UdonSharp の普通の手段で Prefab を作ると、Udon の値が Prefab に入らない。

## 決定

- セットアップの正本は `ScriptableObject` の設定アセット。モデルの対応は、元のモデルのアセットの中のオブジェクトを指す。生成物から設定を逆算しない。
- ウィンドウと AI の連携は、製品の Editor にある同じ検証・生成・配置の処理を呼ぶ。AI 専用の生成処理は作らない。
- 生成は非破壊とする。元のモデルを入れ子の Prefab にし、同じ出力 Prefab をその場で更新する。
- Play 中の調整：数値は再適用（C 案＋W2）、同じ構造の出し直しは A 案＋W2、構造の変更は Play を抜けて生成し直す。作業値は明示したときだけ設定に保存する。
- 開発ワールドは、Git の対象外の専用シーンを更新し、SDK でローカルビルドまで行う。アップロードはしない。

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 生成した Prefab を正本にする | どの設定から作ったかが分からなくなり、作り直しで手の変更が消える |
| AI 専用の生成処理を作る | 利用者の結果を保証しなくなる |
| 元のモデルに部品を足す | 元のアセットが変わり、モデルの更新で消える |
| 生成のたびに新しい Prefab を作る | GUID とシーンからの参照が切れる |
| Play 中に構造を変えて再生成する | UdonSharp の普通の手段では Udon の値が Prefab に入らない |
| 出し直しを「複製して Start を待ってから設定」（B 案）にする | Start までの間、古い値で動く。A 案に対する利点がない |
| 値の書き込みに `CopyProxyToUdon`（W1）を使う | Editor 専用で、状態まで上書きする。W2 にない利点がない |
| 公開済みのワールドを直接更新する | Blueprint ID を取り違えると、他人が使うワールドを壊す |

## 結果

- 良くなること：利用者のウィンドウと AI が同じ車両を作る。作り直してもシーンの参照と GUID が保たれる。
- 引き受けること（欠点・制約）：構造の変更は Play に入り直す必要がある（数秒）。設定アセットの形を変えるときは `schemaVersion` を上げて移行を書く（付録 A-3）。
