# 0007. 起動済みの Editor で AI が検証する

- 状態：承認
- 日付：2026-11-13
- 関連：rules の付録 U の 2 項目と 8 章の役割を、この案件では置き換える（下の「決定」）。[SPEC_2026-11-13_Editor連携とAI開発運用.md](../../02_Specifications/SPEC_2026-11-13_Editor連携とAI開発運用.md)

## 背景

付録 U は「エージェントは Unity を動かせない」「テストは EditMode で書き、ユーザーが Test Runner で実行する」としている。バッチモードで Unity を起動して試したところ、確認 1 回の 6〜7 割が起動と終了の固定費で、そのたびに Editor を閉じる手間もかかった。UdonSharp のコンパイルの誤りは、`-quit` 付きの起動では分からなかった。車両の挙動は Udon VM と ClientSim の上でしか確かめられず、EditMode だけでは足りない。

## 決定

- 起動済みの Editor に、ループバックの HTTP と共通の PowerShell CLI で要求を送る「ローカル Editor 連携」を使う。AI はこれで、コンパイル（C#・UdonSharp）・テスト（EditMode・PlayMode）・生成・開発ワールドの更新・ローカルビルドを行う。
- 連携の実装は、Git の対象外のローカル開発フォルダに置き、公開しない。公開する製品のコードとテストは連携に依存しない。
- この案件で置き換える共通ルール：
  - 付録 U「エージェントは Unity と VRChat クライアントを動かせない」：連携がある環境では、起動済みの Editor を、連携の操作の範囲で AI が動かす。VRChat クライアント・アップロード・見た目と体感・実機の同期は、引き続き人が確かめる。
  - 付録 U「テストは EditMode で書き…ユーザーが Test Runner で実行する」：PlayMode のテスト（Udon Test Kit・ClientSim）も書く。連携がある環境では AI が流す。ない環境では従来どおりユーザーが Test Runner で流す。
  - 8 章の役割：「検証」（指定された検証だけを流し、結果を返す）を足す。
- 付録 U のほかの項目と、rules の本文は置き換えない。

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| バッチモードだけで検証する | 起動の固定費（1 回約 17 秒〜）と Editor を閉じる手間が毎回かかる。Editor を閉じたときの代わりとして残す |
| ファイルを置いて要求する方式を新しく作る | 受付・状態・Reload からの復帰・CLI を一から作る。既にある HTTP の基盤を使えば足りる |
| 最初から MCP にする | Editor 側の実行と復帰の仕組みは別に要る。CLI が安定してから考える |
| 連携も公開する | 参考にした基盤の公開の可否を、別に判断する必要がある |
| 連携を Packages の埋め込みパッケージにする | 公開している `Packages/packages-lock.json` に非公開のパッケージが載る |

## 結果

- 良くなること：起動の固定費と Editor を閉じる手間がなくなる。結果が要求 ID と入力の識別値で残り、レビューで確かめられる。
- 引き受けること（欠点・制約）：clone しただけの環境には連携がない（手動で開発する）。連携の修正は PR で再現できないので、非公開の側に変更の記録を残す。Editor の状態に左右されるので、まっさらな状態の確認にはバッチを残す。
