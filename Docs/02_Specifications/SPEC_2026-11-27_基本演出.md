## 1. 基本演出の仕様

### 目的と用語

乗員と観戦者が、同じ車両の前後進・旋回・停止を見分け、エンジン音を車体の位置から聞けるようにする。ゲームの状態を書き換えるのは既存の走行・武器・生存系。各端末は受け取った状態から表示を作る。親の初期方式案を具体化した #14・#17 に従い、エンジンはループ1本、履帯は左右の AnimationClip を距離で再生する。[親 #9](https://github.com/yakimannzyuu/YakimaTank/issues/9) ／ [#14](https://github.com/yakimannzyuu/YakimaTank/issues/14) ／ [段階6・§8 演出](https://github.com/yakimannzyuu/YakimaTank/blob/05107ef/Docs/03_Architecture/prototype-plan.md)

| 記号 | 定義・単位 |
|---|---|
| V・Ω（表示用速度・角速度） | ワールド空間のベクトル。唯一の運動入力は `Runtime/YakimaTankVehicleSync.cs` の `YakimaTankVehicleSync._GetDisplayVelocity()`（m/s）と `_GetDisplayAngularVelocity()`（rad/s）。内部の `_DisplayValue` はオーナーなら Rigidbody、受信側なら最新の有効な受信速度を返す。受信側で履歴なし・停止印・表示の先読み上限超過なら 0。 |
| v・ω | 車両ルートを基準に v = dot(V, forward)、ω = dot(Ω, up)。+Z 前方、+Y 上方、正の ω は右旋回。モデルや砲塔の見かけの軸を使わない。 |
| b | 左右の履帯中心間隔の半分（m）。モデル補正を適用した車両ルート座標で、b = abs(右転輪中心 x の平均 − 左転輪中心 x の平均) / 2。左右の個数が異なっても側ごとに平均する。 |
| uL・uR | 左の速さ uL = v + ωb、右の速さ uR = v − ωb（符号付き m/s）。前進が正。これはカジュアル走行の表示用の推定値。接地やスリップを解く入力にはしない。 |
| Δs・r・C・φ | Δs = その側の速さ × そのフレームの経過秒（m）、r = その輪の半径（m。転輪は生成半径、回すだけの輪はその輪のメッシュの範囲から求めた半径）、C = その側の履帯が1周期する距離（m）、φ = [0,1) の正規化位相。 |

### インターフェースと更新の順序

1. **生成時に渡す値**　`Editor/YakimaTankSetupService.cs` の `YakimaTankSetupService.Build`、`BuildLookup`、Build 内の `Resolve`、`Wheel` を共用する。元設定の `leftWheels`・`rightWheels` に対応する生成モデル内の表示用 Transform、各 `WheelSpec.Radius`・`Center`、軸・反転・b を同じ順で渡す。設定の `wheelRadius > 0` は既存どおり全輪への手動値、0 は各輪について算出する。`Runtime/YakimaTankVehicle.cs` の `YakimaTankVehicle.leftWheels`／`rightWheels` は物理用 WheelCollider 配列。これらを演出で回さない。転輪に物理・砲塔等のゲーム用 Transform を含むモデルでは、その枝を回さず表示専用の対応を前提とする。回すだけの輪（`leftExtraWheels`・`rightExtraWheels`）も同じ解決で生成モデル内の Transform に結び、半径は各輪のメッシュの範囲から求める（`wheelRadius` の手動値は使わない）。回すだけの輪は b の計算に入れない。
2. **実行単位**　生成車両の専用子に `Runtime/YakimaTankVehicleEffects.cs`（新規案）を1つ、同期方式 None で置く。ルート、車体同期、生存状態、生成済みの音源・Animator を生成時に直結。各輪の初期回転と側の位相を一度初期化し、毎描画フレームに1回だけ速度2本を取得する。左右の速さ・Δs・負荷は同一 Udon 内で共有する。毎フレームの階層探索、素材生成、入力アダプターへの問い合わせは不要。
3. **表示を適用**　各輪は初期 localRotation × ローカル軸の回転（積算角 × 180/π、反転時は負）。角度と位相を毎回折り返して長時間走行の桁落ちを抑える。初期の停止判定は側ごとに |u| < 0.01 m/s を 0 とする。左右反転は転輪だけに適用し、履帯の正方向はクリップの向きで決める。実行開始・復帰の最初のフレームは Δs = 0。
4. **生死を反映**　運動以外の抑止条件だけは `Runtime/YakimaTankLife.cs` の `YakimaTankLife._IsDestroyed()` と既存の `respawnGeneration` を読む。#14 単独ではローカル更新で状態の変化を検出し、破壊優先で積算を止めて音を止める。復活を検出したら走行表示用の初期化処理を1回適用。#15 から同じ初期化を利用可能な形にし、通知と更新が同フレームでも同世代への二重適用を防ぐ。#7 の健在→健在リセットは確定通知に合わせる。#7 通知のシンボル名は未確認。エンジン音は加えて `Runtime/YakimaTankVehicleSync.cs` の `_HasDriver()` を読む（運転手の ID は既存の同期で、オーナー・受信側とも同じ値）。
5. **後続 Issue の接続契約**　`Runtime/YakimaTankWeaponSync.cs` の `YakimaTankWeaponSync._LaunchShell` で実際に `shell._Launch` された発射を使う。受信側の `_AcceptState` と `ShouldShowFire` は、時刻を検証したうえで初回を除外し、番号の変化を判定する。単純な番号の大小比較に置き換えない。`Runtime/YakimaTankShell.cs` の `YakimaTankShell.Update` が呼ぶ選択関数は **`YakimaTankWeaponSync.ChooseHit`**。採用された `hits[chosen]` の点・法線が着弾の根拠で、`_Stop()` は寿命切れでも通る。`YakimaTankLife.Start`／`_NotifyChanged(bool respawned)` が破壊の持続表示を反映する。破壊の瞬間の表示は、演出の側が直前に知っていた HP（健在）を覚えておき、HP 0 になったのを見たときだけ出す。`Start` での反映と初回の受信では出さない（今の `_NotifyChanged(bool respawned)` は直前の HP を渡さないので、比べる値は #15 で持たせる）。演出の Prefab の複製を生成時に置く処理（着弾の数は砲弾と同じ）も #15 が担当する。#14 で定義するのは要求と素材の型まで。これら3つの既存 Runtime ファイルへの戦闘演出の結線は #15 が担当する。[#15](https://github.com/yakimannzyuu/YakimaTank/issues/15)

### 履帯クリップのスクラブ方式と #17 への出力契約

| 方式 | #14 の評価方法・利点と制約 | #17 が渡すもの |
|---|---|---|
| **Animator の状態スクラブ（採用）** | 生成車両をルートとする表示用 Animator 1個。左右2レイヤー、各1状態、レイヤーウェイト1、遷移なし、状態速度0、Write Defaults オフ、Root Motion オフ。明示したレイヤーと状態に `Animator.Play(int, int, float)` で φ を設定する。共通 Renderer 上の別々のプロパティも左右独立にできる。停止保持・逆方向・同フレームの両レイヤー評価を SDK で確かめる。 | 左右別の通常の `.anim`、各側の周期距離、位相スクラブ／ループという駆動情報。クリップは Animator ルートからのパス（生成車両の `Model/…`、Model 自身は `Model`）で対象の `blendShape.*` のみを駆動。#14 の生成側がクリップを所定の2状態へ割り当てる。 |
| Playable の手動評価 | 左右の `AnimationClipPlayable` の時間を φ × clip.length 秒に設定してグラフを評価する。各クリップの時間を直接扱える。出力の合成、グラフ生成・破棄、Udon からの API 公開範囲の確認が増える。 | 左右クリップ、周期、同じバインド基準。状態名・専用 Controller は不要。グラフの結線と破棄は再生側。 |
| クリップの直接サンプリング | Unity の `AnimationClip.SampleAnimation(GameObject, float)` で同じルートに秒を指定。2本が異なるプロパティだけを書くモデルに向く。既存 Animator との評価順、Udon 公開範囲、両側が上書きしないことの実証が必要。 | 同じ通常のクリップ＋周期。直接サンプルする対象ルートと相対パスを一致させる。状態・グラフの生成は不要。 |

対象は SkinnedMeshRenderer、クリップが動かすのはシェイプキー（`blendShape.*`）だけとする。テクスチャをずらす履帯（材質のプロパティを動かすクリップ）は 0.7.0 では扱わない（2026-11-27 に見送り、第3節の5）。

3案とも **対象 SDK 3.10.6 上の Udon 公開・実際の評価結果は未確認**。Unity API の実在と Udon VM での実用可否を区別する。T1 で Animator.Play のオーバーロードを Class Exposure Tree で確認し、手作り2クリップで正送り・逆送り・停止・片側欠落を試す。採用方式が通らない場合は失敗条件を記録し、代替案に切り替える前に SPEC の変更をやきまと確認する。転輪・音・移行は独立して進められる。[Animator.Play](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Animator.Play.html) ／ [Playables Examples](https://docs.unity3d.com/2022.3/Documentation/Manual/Playables-Examples.html) ／ [SampleAnimation](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/AnimationClip.SampleAnimation.html) ／ [VRChat Class Exposure Tree](https://creators.vrchat.com/worlds/udon/udonsharp/class-exposure-tree/)

**共通の受け渡し**　0→1 が前進1周期、両端の見た目が一致し、イベントとルート移動を含まない。左右のバインド（パス・コンポーネント型・プロパティ）の積集合は空。同一 SkinnedMeshRenderer も別プロパティなら可。対象の参照を設定した場合はクリップの相対パスの解決先がそれと同じであることを照合する。未指定ならクリップのバインドで一意に解ければ再生可能。左右同名の階層などで一意に解けない場合は該当側を誤駆動しない。既存モデルの Controller は置換しない。親子 Animator や既存カーブとの二重駆動を実機で確認できない組合せは未確認として扱う。

#14 は手作りのクリップを設定から結線できる。Controller を補助アセットとして保存する場合は出力 Prefab ごとに生成所有を限定し、更新失敗時には Prefab と以前の Controller の組を復元する。#17 は編集可能なクリップと周期を同じ入口に渡す。シェイプキー名・順序、キーポーズ、検出・生成レシピ、手調整の保護は #17 の Editor 側の別データで管理できる。レシピから既存の設定を指す形なら第2節への追加は不要。再生側へレシピを持ち込まない。[#17](https://github.com/yakimannzyuu/YakimaTank/issues/17)

### エンジン音の負荷とピッチ・音量

負荷には左右の絶対速度の平均を使う。a = (|uL| + |uR|)/2 とし、目標負荷 t = clamp01(a / 基準速度)。外側履帯だけの瞬間的な加速に反応しすぎず、同じ速度なら前進・後退・超信地旋回が同じ音になる。代案の max(|uL|,|uR|) は片側だけ動く旋回が強く聞こえる。例として左4、右0 m/s、基準4 m/sなら、平均方式は0.5、最大方式は1.0。|uL+uR|/2 では超信地旋回が無音負荷になるため採用しない。

負荷だけを1回平滑化する。時定数 τ のとき係数は 1 − exp(−Δt/τ)、τ = 0 は即時。負荷 h でピッチと音量を各々のアイドル値から最大値まで線形補間する。音源は車体に追従し、loop を有効、playOnAwake を無効、spatialBlend を1とする。破壊時は直ちに停止し平滑化の残りを捨てる。運転手がいなくなったら、ピッチはそのままに音量を同じ時定数 τ で0へ下げ、0.01 未満になったら止める（τ = 0 なら直ちに止める）。次に運転手が乗ったら、負荷0（アイドル）から頭出しして鳴らす。クリップ未指定ならその音源は休止。#15 にあるエンジン音サンプルの存在は Issue の記載で確認、ファイルのパス・実音・再配布条件は未確認。下表は承認した既定値での定常出力。実素材での聞こえ方は人間確認で記録する。

| 左・右（m/s） | 定常負荷（基準4 m/s） | pitch | volume |
|---|---:|---:|---:|
| 0・0（健在、運転手あり、停止） | 0 | 0.80 | 0.20 |
| 2・2／−2・−2／2・−2 | 0.5 | 1.10 | 0.50 |
| 4・4 またはそれ以上の同速 | 1 | 1.40 | 0.80 |
| 運転手なし（健在） | 保持 | 保持 | 0 へ下げて停止 |
| 破壊中 | 値を初期化 | ― | 音源停止 |

### 演出の Prefab の再生

| 対象 | 置き方 | 再生する時 | 止める時 |
|---|---|---|---|
| 閃光 | 砲口の下に複製1つ | 発射ごと（FX-FIR-01） | 次の発射で無効→有効 |
| 着弾 | 複製を砲弾と同じ数。ワールドの位置に残す | 着弾ごと（FX-IMP-01）。複製を順番に使い、一巡したら最初に戻る | 次に同じ複製を使うとき |
| 破壊の瞬間 | 車両に複製1つ | 破壊を見ていたときに1回（FX-DST-02） | 次の破壊のとき |
| 破壊中 | 車両に複製1つ | HP 0 の間は有効（FX-DST-01） | 復活・リセットで無効 |

- 「再生」は複製を無効→有効にすること（FX-PFB-01）。ParticleSystem・AudioSource は Play On Awake で始まるように作る。Prefab に Udon は要らない。
- 着弾音・破壊の音は、その Prefab の中の AudioSource で鳴らす。発射音だけは `fireClip`（砲口の音源）で鳴らす。
- 1回もの（閃光・着弾・破壊の瞬間）にループするパーティクルや音を入れると鳴り続ける。Prefab に UdonBehaviour・コライダーがあると、同期・砲弾・プレイヤーとぶつかる。どちらも #16 の検証で Warning にする。

*残すもの*　既存のモデル・車体・左右転輪配列の参照と順序（砲塔・砲身は砲塔のリストの要素0へ移して残す）、走行・足回り・乗降・入力・同期・接触・武器・HP・復活の数値、`outputPrefabPath`、`placementId`、`hasPlacement`、`placementPosition`、`placementRotation` はリネーム・再採番・再初期化しない。版0や未来版は既存の検証に従いエラー。読込時に外部アセットを書き換えず、明示保存まで従来の保存契機を維持する。v7 を再読込しても新しく指定した clip や反転設定を既定に戻さない。旧版の YAML から追加列を実際に欠落させて検証する。

*画面と診断の対応*　FX-STR-01 で非表示の構造に診断が出ても、手順8から修正先に到達できるようにする。FX-OPT-01・FX-TRK-01 では、各側の対象・クリップ・周期について、任意の空欄、一意に解けた対象、解けないパスを区別する。FX-TUN-01 の作業値には共通検証を適用し、設定への保存と生成 Prefab への反映を別々に示す。操作は画面 SPEC 1.1・1.2・1.6・1.8 に従う。診断の移動先、候補の分類理由、最後に車両へ適用した値は演出の設定リストに追加しない。

*永続化しないもの*　b、個別半径（回すだけの輪の半径を含む）、生成先 Transform／Animator／Controller の参照、実行中の位相・角度・負荷、再生フラグ、生死・世代のコピーは導出値。砲口の基本位置・発射方向は既存の武器生成に従う。#10 の画面区分、診断選択、旧パス候補、生成が成功したかを示す署名は利用者が設定するモデルの項目に足さない。#10 用に保存するのは、砲塔のリストの要素の `muzzle` だけ。入力欄と明示指定の書き込み・適用は #10 で追加する。null の場合は `Editor/YakimaTankSetupService.cs` の `FindMuzzleMarker` → `MuzzlePosition` 内のメッシュ前端フォールバックを使う。[#10](https://github.com/yakimannzyuu/YakimaTank/issues/10) ／ [現行の設定](https://github.com/yakimannzyuu/YakimaTank/blob/05107ef/Assets/Yakimannzyuu/YakimaTank/Editor/YakimaTankSetupSettings.cs)
