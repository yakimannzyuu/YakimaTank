## タスクと依存関係（Claude Code 用）

**完了地点**　1台の生成車両を操縦者と観戦者から確認する。転輪・回すだけの輪と履帯は各側の移動距離どおりに動き、音は運転手がいる間だけ車体位置で鳴り、演出の数値は Play 中に再適用でき、同じ車両が素材なしでも走行・戦闘できる。1回のスキーマ改定に後続の素材枠を含める。

**進め方**　各行は Claude Code の1セッション単位。T0 → T1・T2、T2 → T2b・T4、T2b → T3、T3＋T4 → T5、T5 → T6、T1＋T5 → T7、T6＋T7 → T8。T1 が SDK 待ちの間も T2〜T6 の独立部分は進められる。T0・T0b・T0c は完了。セットアップ画面の作り直し（[セットアップ画面 SPEC](SPEC_2026-11-27_セットアップ画面.md)）は T2b の後に入れると、固定1組の入力を要素0に直接つなげられる。次のセッションは T1 の SDK 確認から始める。T1 の方式検証で永続項目の変更が必要と分かった場合は、T2 のスキーマ変更を確定する前に SPEC に戻る。Claude Code はテストと観察手順を用意し、**Unity のコンパイル・テストの実行・VRChat 確認はやきまが行う**。実装が済み、結果を待っている項目だけ「実装済・検証待ち」と記録する。

- **#15** は同じ SPEC の FX-FIR-01／FX-IMP-01／FX-DST-01／FX-DST-02／FX-PFB-01、保存済みの発射音・4つの Prefab 枠（破壊の瞬間を含む）、車両ごとの演出 Udon、走行表示を初期化するローカル契約を使う。Prefab の複製を生成時に置く処理（着弾は砲弾と同じ数）と、その数の試験も #15 が持つ。#14 の完了条件に戦闘演出の再生合格を含めない。
- **#16** は FX-GEN-02 と統合受け入れ、演出設定の診断（回すだけの輪の Error、Prefab の UdonBehaviour・コライダー・1回ものに入ったループの Warning を含む）、再生成一式、FX-SMP-01 のサンプル素材、v0.7.0 の記録を担当。4台の基準手順は PR #4／同期 SPEC §1.3、6台計測は #6 の実施結果を記録する。
