## メモ

- 1.8 の確かめ（2026-11-17）：
  - `[NetworkCallable]` の入口（`ReceiveHit`）・`NetworkCalling.CallingPlayer`・引数つきの `SendCustomNetworkEvent` は UdonSharp でコンパイルできた。
  - ClientSim では、撃った砲弾が相手の命中用のトリガーに当たると、申告が届いて相手の HP が減った（PlayMode）。
  - 1 秒あたりの回数の上限：SDK 3.10.6 の Udon Graph の検証では、既定 5、最大 100。装填の時間は送る間隔（既定 0.1 秒）より長いので、1 台が撃てるのは 1 秒に 10 発まで。その全部が当たっても届かない 10 にした。上限を数える単位（送る側ごとか、受ける側の合計か）と、超えた分が遅れて届くのか消えるのかは、SDK からは分からなかった。VRChat で確かめる（仕様 5 節）。
- 確かめる順番：オーナー → 撃った車両の番号 → 送った人 → 世代 → HP → 番号が負 → 重複。撃った車両の番号が範囲の外だと、その車両の武器のオーナーを引けないので、送った人より先に見る。どれで外れても使わないことは仕様と同じ。
- 一度も送っていない状態を弾く：同期変数の HP の初期値を -1 にし、受けた側の確かめで弾く（途中参加の人が、送られていない初期値を「HP 0 の破壊」と読まない）。
- 処理した命中の配列の長さ：シーンの車両の一覧が始まる前は分からないので、受けた側は一覧を知るまでシーンの車両の数と比べない。オーナーは送る前に一覧の数まで伸ばす。
- Start の前に届いた状態も使う（途中参加の最初の状態を落とさない）。
- HP のバーの大きさ（幅 1.2 m・高さ 0.12 m）は仮の見た目の値。設定にはしない。
- 確かめていないこと：VRChat が、同じ GameObject の Manual の Udon（車両・車体の同期・生存の状態）を、どれか 1 つの送る要求でまとめて送るか。まとめて送るなら、生存の状態は車体と同じ頻度で送られ（送る量が増える）、命中のたびに車体の状態も 1 回余計に送られる。VRChat で、撃たれたときにデバッグ UI の Sent/s が増えるかを見る。
- 重複の判定（仕様 1.2 の 6）のため、同じ撃った車両から、後に撃った弾が先に当たると、前に撃った弾の命中は数えない。既定値（装填 3 秒・寿命 3 秒）ではほぼ起きない。装填の時間を寿命より短くすると起きうる。README と仕様 5 節に書いた。装填の時間と寿命の関係を検証の Warning にする案は採らなかった（正しい設定でも出てしまう）。
- 申告の水増し：確かめるのは、送った人が撃った車両の武器のオーナーかまで。武器のオーナーが撃っていない命中を申告すること（改造したクライアントなど）は防げない。受けた側に見えている撃った車両の発射の番号と比べる案は、武器の同期が申告より遅れて届くと正しい命中を捨てるので、この版ではしない。README に書いた。
- 実装の後のレビューで足したテスト：破壊の間は座っていても撃てない（座席が降ろす前の間）、Start の前に届いた生存の状態を使う。どちらも、実装の該当の条件を一時的に外すと失敗することを確かめた。
- 構成の決定（撃った側の申告とオーナーの確かめ）は、ADR 0009 の末尾に注として足した（0009 の採らなかった案の「反力を毎フレームのネットワークイベントで送り合う」とは別の用途）。
