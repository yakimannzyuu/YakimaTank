## メモ

- 1.10 の時間軸：VRChat の文書（Udon の Networking の部品の説明）に、`sendTime` と `receiveTime` は受ける側の `Time.realtimeSinceStartup` の時間軸とある。`SimulationTime` は `Time.realtimeSinceStartup - SimulationTime` を遅れとして使う例があり、同じ時間軸と読める。止まる条件には当たらない。実際の値は VRChat のローカルテストで Age を見て確かめる（5 節）。
- 1.10 の WheelCollider：開発用のモデルの 2 台（同じオーナー）を秒速 2 m で正面と横から当てた（開発用の一時的なテスト、PlayMode e3e4b312）。`Physics.IgnoreCollision` なしでは当てた側が相手に止められ（1.0 m・0.3 m しか進まない）、ありでは 16.9 m すり抜けて、相手の移動 0.000 m・当てた側の高さの変化 0.001 m。WheelCollider も従う。止まる条件には当たらない。仕様の PlayMode のテストで改めて確かめる。
- ClientSim は `OnDeserialization` に `sendTime` = 0 を渡し、`SimulationTime` を実装していない。呼んでも例外にはならないが、`Time.realtimeSinceStartup` と関係のない値を返す（6.16 に対して 0.49）。`IsClogged` は ClientSim の前は true、後は false。
  - 表示する時刻：`SimulationTime` から求めた遅れ（`Time.realtimeSinceStartup - SimulationTime`）が 0〜2 秒のときだけ `SimulationTime` を使い、それ以外は「今の時刻 − 送る間隔の 2 倍」にする（仕様 1.10 の「時間軸が違えば」を実行中に判断する）。ClientSim では代わりの時刻になる。
  - PlayMode では `_AcceptState` に、状態と送った時刻（`Time.realtimeSinceStartup` の軸）を直接入れる。
- ClientSim で所有権を移せるのは、`VRCObjectSync` などがある GameObject だけ。テストは Udon Test Kit の `Session.SetOwner` で移す（その後は `Networking.SetOwner` も効く）。
- 部品の形（名前は仕様の仮の名前のまま）：
  - `YakimaTankVehicleSync`（ルート、Manual）：同期変数は仕様 1.3 の表。受けた状態は、同期変数と `incomingSendTime` から `_AcceptState()`（引数なし）で読む。`OnDeserialization` は `incomingSendTime` に `sendTime` を入れてから呼ぶ。PlayMode は `SetProgramVariable` で入れて `SendCustomEvent` で呼ぶ。
  - 送るかの判断は静的な関数 1 つ（動いている・止まってからの時間・停止を送ったか・前の要求からの時間・間隔・ずれ・詰まり・保留中の送信）。「すぐに送る」と「詰まりが解けたら最新を 1 回」は、保留中の送信の印で扱う。
  - 履歴（8）と保留（4）は、同期の Udon の並んだ配列。U# の自作の関数は out 引数を使わない。
  - 車両の Udon に、物理を計算してよいか（オーナーか）の印を持たせる。印がないと `FixedUpdate` と `SetDriveInput` は何もしない。
  - すり抜け：自分の物理の形を有効にしたとき（Start・所有権を取ったとき）に、一覧のほかの車両の全部のコライダーと `Physics.IgnoreCollision` する。持ち主が違う車両は、相手の物理の形が無効なので、外しても変わらない。所有権のたびに組み合わせを選び直さなくて済む。
- デバッグ UI の数値：Udon は `TextMesh` の文字を書けない（公開されていない）。`UnityEngine.UI.Text`（ワールド空間の Canvas、フォントは Unity 内蔵の LegacyRuntime）で書く。
- 計算のテストは、中身のない関数で 25 件すべて失敗することを確かめてから実装した（EditMode c383dced）。
- 車両の Udon を None から Manual に変えると、U# はコンパイルのときに、シーンに置いた車両のインスタンスの同期方式を直す（シーンが未保存になる）。利用者が版を上げたときも同じことが起き、配置の確かめが「手で変えた所」として止まるので、配置は、スクリプトの指定に合わせた同期方式の上書きを手の変更とみなさない。開発シーンは、ユーザーが 2026-11-15 にチャットで「保存する」を選んで保存した。
- ClientSim は、ワールドのオブジェクトの Manual の同期で OnPreSerialization・OnPostSerialization を呼ばない（プレイヤーの保存の仕組みだけが呼ぶ）。所有権の移動（`Session.SetOwner`）では、その場で `OnOwnershipTransferred` を呼ぶ。PlayMode は、送る要求が増えたらテストが OnPreSerialization・OnPostSerialization を呼ぶ。
- 同期の PlayMode は、走行のテストの基底の別のファイル（`YakimaTankDriveTestBase.Sync.cs`）に置き、テスト用のモデルと開発用のモデルの両方で流す。シーンの車両の一覧の Prefab は、Play の前（`IPrebuildSetup`）に作る。
- 0.2.0 でビルドしたシーンでは、シーンの記述子の Network ID に、車両のルートの型（同期の Udon を足す前）が記録されていて、SDK のビルドの前処理（AssignSceneNetworkIDs）が「Failed to assign network IDs」で止まった。ユーザーが 2026-11-15 にチャットで「自動で直す」を選び、仕様 1.11 を足した。配置・一覧の更新・ビルドの前の確かめで、車両の中を指す型の古い ID を外す（SDK がビルドで新しい ID を付ける）。
- 型の比べ方は SDK の Network ID Utility と同じ（`NetworkIDAssignment.GetSerializedTypes` と記録の `SequenceEqual`。型の記録がない ID は合うとみなす）。
- 境い目の値（0.05 m・1 度）ちょうどの EditMode の確かめは、float の丸めで転ぶので、少し越えた所で確かめる。
