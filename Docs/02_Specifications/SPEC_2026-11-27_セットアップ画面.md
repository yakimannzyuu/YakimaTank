### 1.1 全体の形（論点 1B）

| 場所 | 中身 |

- 設定アセットを選んでいないときは、今と同じく、設定アセットの欄と「新しく作る」だけを出す。
- ウィンドウの幅が狭いときは、左の手順を上のポップアップに畳む（幅は 6.1）。

#### 検証・生成・配置の状態を区別する

下帯と手順8に、①現在の設定の Error／Warning、②その設定から生成した出力 Prefab の状態、③アクティブシーンの配置対象と結果を別々に示す。✓ は診断なしを表す。出力は「未生成」「現設定で生成済み」「変更後・再生成が必要」「照合未確認」を区別する。共通の生成が保存後の検査まで成功したときだけ、その時点の生成入力と出力を対応づける。モデル・再生成対象の入力・出力の差し替えで対応が崩れたら更新が必要とする。画面外からの共通生成も同じ基準で扱い、過去の対応を確かめられない場合は未確認とする。この状態を設定項目に追加しない。

生成失敗時は、前の出力・既存配置が保たれたかを共通処理の結果に従って表示する。古い出力や照合未確認の出力を現設定の結果として新規配置・更新できないようにし、次の操作を生成へ戻す。すでに配置した車両はその場に残す。シーン描画も現設定との一致を確かめてから行う。旧モデルに同名パスが見つかっても現モデルの確認済み表示にしない。

#### 480 px 未満でも別手順の Error に到達する

幅480 px未満では、ポップアップの候補にも手順別の Error／Warning 件数を残す。下帯の件数・状態文から、手順8の診断一覧を開けるようにする。生成ボタンが無効でもこの移動は使える。狭幅では長い理由を折り返し、必要に応じてボタンを次の段へ送る。幅を戻した後も、選択中の手順と到達した診断行を保つ。

#### 任意の演出と片側の履帯の原因を示す

手順1は初回生成に必要な部位を先に置き、任意の砲口・見た目の部位には任意の印を付ける。手順6の6小見出しを保ち、履帯では左右別に、手順1の対象と手順6のクリップ・周期の組合せを表示する。反対側への設定を要求しない。対象が空でクリップから一意に解ける場合、クリップがなくその側だけ休止する場合、指定した部位・クリップのパスが一致しない場合を区別する。対象の修正は手順1の同じ側、素材の差し替え・パスの修正・周期の調整は手順6の同じ側へ案内する。素材内のパスに問題がある場合はクリップと該当パスを示す。再生可否・診断は共通処理の結果を使う。

### 1.3 項目の名前と表示の言語（論点 6B と追加の決定）

項目の名前を、上の帯の「表示」で切り替える。

| 表示 | 項目の名前 | 説明（ツールチップ） |
|---|---|---|
| 日本語（既定） | 日本語の名前と単位。例：質量（kg）。決まった用語（Prefab・WheelCollider・Udon・VR など）は訳さない | 日本語の説明。最後に変数名（例：`mass`） |
| ネイティブ | 設定アセットの変数名そのまま。例：`mass`。AI の連携（`YakimaTankSettingsWriter`）・設定アセットのファイル・README の表で使う名前と同じ | 日本語の名前と説明 |

- 手順・見出し・ボタン・メッセージは、どちらの表示でも日本語のまま（6.1）。メッセージの頭に付ける項目名だけは、表示に合わせる。
- 表示の言語は、その PC の Unity の設定（EditorPrefs）に覚え、設定アセットにも Git にも入れない（6.1）。
- 名前・単位・置く手順は、1 か所の表（`YakimaTankFieldLabels`。名前は案）に持つ。表にない項目は、どちらの表示でも変数名を出す。
- 繰り返しのグループ（砲塔・装甲の要素）の項目名は、グループの見出しと要素の中の名前で組み立てる。日本語は「砲塔 1・砲身」（番号は 1 から）、ネイティブは `turrets[0].barrel`（番号は 0 から。AI の連携が要素を指す名前と同じ）。
- 見出しは画面が 1 回だけ描き、設定クラスの `[Header]` は画面に出さない。設定アセットの Inspector は今のまま。

#### AI と項目名・モデル内パスを往復する

日本語／ネイティブのどちらからも、行のネイティブ識別子をコピーできるようにする。参照の札ではモデルルートからの完全な階層パスも別にコピーできる。項目の添字（例 `leftWheels[1]`）と、モデル内で同名兄弟を識別するパスの添字（例 `Axle/Wheel[0]`）を区別する。同名・予約文字を含む部位パスの生成と照合は `YakimaTankModelPaths.GetPath`・`TryResolve` の表記に従う。

AI から返ったネイティブ識別子で該当行・配列要素へ移動できるようにする。パスはその行の部位ピッカー内で照合し、明示選択でだけ割り当てる。存在しない識別子・範囲外の添字・解けないパスでは対象を変えず、理由を示す。表示識別子と Writer の要求形式を区別し、T2b の既存の単数パス指定と T3 以降の要素指定を同じ入力例として扱わない。

### 1.4 部位の選び方（論点 3C）

- 部位の欄を押すと、検索できる階層の一覧（AdvancedDropdown）を出す。
  - 名前の一部で絞る（大文字と小文字を区別しない）。
  - 各行に、階層パス・メッシュの有無・左右（向きの補正を掛けたモデルの座標で、x の符号。中央付近は「中央」。幅は 6.2）を出す。
  - いちばん上に「候補」の組を出す。
- 候補は `YakimaTankModelInspector` が名前から出すもの（車体・砲塔・砲身・輪）。輪は、転輪と回すだけの輪を名前で分け（6.2）、左右に分ける。もう入っている部位とメッシュのない部位は出さない。
- 配列の欄（左右の転輪・回すだけの輪）は、入っている部位を札で並べ、× で外す。「＋」で一覧を出す。一覧の下に「候補から左に n 個入れる」を置き、まだ入っていない候補を前から順に足す。
- 砲塔のグループでは、要素ごとに候補を出す。ほかの要素に入っている部位も、候補に出さない。
- 候補は押したときだけ入る（0.1.0 で決めた「対応を自動で推測しない」を続ける）。
- 候補の決め方（名前の分け方・「中央」の幅）は 6.2 の値で作り、やきまがローカルの参考モデルで確かめて調整する。公開するコードとテストには、参考モデル固有の名前や値を書かず、どのモデルにも通じる決まりとして書く。

#### 候補の分類理由を比較する

全階層側では、選んだ部位について、名前から見た輪の区分、向き補正後の横位置と左右／中央の結果、メッシュの有無、割り当て済みの欄、候補に含めた／外した理由を確かめられるようにする。やきまは同じモデル・同じ部位パスを使い、ローカルで条件を調整した前後の結果を照合できる。理由は候補を計算した共通処理から取得する。分類を確認しただけでは割り当てを書かない。6.2 の値・公開用データの扱いは承認済みの手順に従う。

### 1.5 シーンビューに描く（論点 4B）

- 手順1（Play 中は専用画面）の切り替えがオンで、開いているシーンにこの設定の生成 Prefab の車両があるとき、その車両の上に描く。手順 1 に描いている車両の名前を出し、候補が複数あるときは選べるようにする。既定は配置の車両で、なければ最初に見つかった車両。
- 描くもの：

| もの | 描き方 |
|---|---|
| 選んでいる部位（手順 1 で今の行、またはマウスを乗せた行） | 範囲の箱（橙） |
| 転輪 | WheelCollider の円（緑） |
| 回すだけの輪 | 点線の円 |
| 輪の前進で回る向き | 矢印。輪を回す設定・軸・反転から求める（演出の項目ができてから） |
| 砲口・座席・車体のコライダー | 点（赤）・点（黄）・細い線 |

- 部位は、設定の参照から階層パスを求め、車両の `Model` の下で同じパスを探して描く。描画の前に 1.1 の生成状態を確認する。見つからない部位（生成の後に変えた部位など）は描かず、「生成し直すと描きます」と出す。
- 車両がないときは、手順 1 に「生成して置くと、シーンビューに描きます」と出す。
- Play 中も描く（輪の向きを確かめながら調整するため）。描くだけで、シーンは変えない。
- 切り替えの状態は EditorPrefs に覚える。既定はオン。

#### シーン描画と Play の対象を一致させる

同じ設定からの車両が複数あるときは、名前に加えシーン名と階層パスで区別する。同名兄弟には順番など、同じシーン内で一意に選べる手掛かりを付ける。Play 中は専用画面にも対象選択と描画オン／オフを置き、描画先と再適用先で選択を共有する。描画をオフにしても調整対象は保持する。出し直し成功時は返された置換先へ両方を移す。選択車両が消え、対応する置換先が分からない場合は未選択とし、残りの車両へ自動適用しない。初回の既定選択と EditorPrefs の描画設定は従来どおり。

### 1.6 検証の出し方（論点 5B）

- 次のときに検証し直す。画面を描くたびには流さない。
  - 値を変えたとき
  - Undo・Redo のとき
  - 設定アセットを選び直したとき
  - ウィンドウが前に出たとき
  - 設定アセットが外から変わったとき（AI の連携が書いたときなど）
- 結果は、診断の項目名（`SetupDiagnostic.Field`）から行を決め、その行のすぐ下に出す。配列の項目は、その配列の行の下に出す。項目名が空の結果は、手順 8 の一覧の先頭に出す。
- 手順の印と、下の帯の件数にも出す。手順8の一覧から、表示されている項目は該当行へ、非表示の項目や全体診断は案内した修正先へ移動できる。
- 「検証」のボタンはなくす。

#### 非表示の項目から復旧する

手順8では、編集行がない診断に項目名・現在値・0.7.0 の条件・修正先を表示する。`driveType` の Error には WheelCollider、`seatRoles` の Error には不足する操縦・砲手を示す。対象の設定アセットを Inspector で開けるようにし、そのフィールドを直して画面に戻ると再検証して診断を更新する。`turrets` が0組なら手順1の固定欄へ、2組以上なら Inspector で残す組を利用者が確認して整理する。余分な要素を自動で削除しない。`armorZones` に要素があることだけの Warning には、値を保持して生成でき、0.7.0 のダメージは一律であることを示す。全体診断には手順8で実際の修正先を示す。

#### 診断から対象の札へ移動する

診断一覧の行を押すと対象手順を選択し、必要な折り畳みを開き、該当行を見える位置までスクロールする。空・旧参照・重複の転輪は、フィールド名に加え、現在の配列位置と部位パス（空なら位置のみ）で対象の札を強調する。左右に重複する場合は両方の札へ移動できる。本数違いの Warning では左右件数と走行への影響を示し、意図した非対称なら生成を続けられる。修正後は再検証した結果を使い、古い配列位置に飛ばない。位置やパスは共通診断から受け取り、画面で日本語メッセージを解析しない。

### 1.7 モデルの差し替え（論点 7B）

- 部位の参照のうち、今のモデルの中を指していないものを見つけたら、手順 1 の先頭に「確かめる項目」を出す。モデルを替えたときも、ほかから設定が変わったときも、同じ見つけ方をする。
- 各参照について、元のアセットの中の階層パスを求め、新しいモデルで同じパスを探す（`YakimaTankModelPaths`）。見つかった・見つからないを並べる。
- 「見つかった n 項目を結び直す」を押すと、見つかった参照のうち確定対象に含めた n 件だけをまとめて書く。Undo 1 回で戻せる。
- 見つからない参照は、消さずに赤のまま残す（今のような、何も言わずに「なし」に戻すことはしない）。残っている間は、検証が Error で生成を止める。
- 履帯のクリップのパス（`Model/…`）が新しいモデルで解けないときは Warning を出す（演出の項目ができてから）。
- 砲塔のグループの各要素と、装甲の要素の部位も、同じ決まりで結び直す。
- 数値は変えない。

#### 同名の輪を確認し、配列の同じ位置で直す

結び直しの各行に、割当先（左右・配列位置）、旧・新のモデル名と完全な部位パスを並べる。同名兄弟の添字は同名内の順番を表す。前後の輪が入れ替わっても一致し得るため、番号付きパスは旧・新の補正後の位置などを比較し、該当行を個別に確認してから一括確定に含める。照合できない場合は手動指定へ進める。確定前に残る件数を示す。

見つからない札から新モデルの階層を開き、その配列位置で置換する。置換後も他の札の順序を保持する。任意の参照は「この割り当てを外す」を明示して解決でき、必須条件を欠く場合は Error を残す。未確定・取り消しでは参照を保持し、確定した一括操作は Undo 1回で戻す。

### 1.8 Play 中の画面（論点 8B）

- Play に入ったら、右の中身を「Play で調整」の画面に替える。手順の中身は読むだけにする。
- 「Play で調整」の画面：
  - 対象の車両：この設定の生成 Prefab のインスタンスと、この Play の間にこの画面で出し直した車両だけを出す。手で置いた車両も、生成 Prefab のインスタンスなら入る。台数を出す。
  - Play 中に再適用できる数値を、手順の組ごとに並べる。設定と違う値の行は青い線を引き、設定の値を横に出す。
  - 「再適用」「出し直し」「設定に保存（n 項目）」。保存は、変えた項目の一覧（名前・設定の値 → 作業値）を画面の中で見せてから書く。
- 作業値は今までどおり、Play を抜けると捨て、保存したときだけ設定に書く（ADR 0008）。
- これで `Docs/04_Development/TODO.md` の「Play 中の調整の対象を絞る」は片付く。

#### Play の作業値を検証してから操作する

設定アセットの診断と、Play の作業値を反映した設定の共通検証結果を区別する。作業値を変えたら該当する Play の行直下に理由を出し、再適用・出し直し・設定に保存の確定時にも同じ内容を検証する。Error があれば3操作とも実行せず、車両・設定アセット・作業値をそのまま保って修正できるようにする。Warning のみなら影響を示して続行できる。対象車両がないときは、車両を必要とする操作にその理由を出す。

#### 未適用・試した値・保存済みを見分ける

青線は設定アセットとの差を表す。各作業値が選択中の車両へ最後に正常に適用した値と同じかも示す。適用記録がなければ「適用未確認」、再適用後の再編集は「未適用」と表示する。再適用は対象車両を初期位置に戻し、出し直しは車両を置換することを押す前に示す。どちらも成功時だけその車両の適用記録を更新する。

保存前の一覧で設定値・保存する作業値・対象車両に最後に適用した値（記録がなければ未確認）を照合できるようにする。未適用の値も明示して保存できる。確認中に対象設定・作業値・元の設定値が変われば一覧を取り直し、外部更新を古い作業値で上書きしない。保存は設定アセットだけに書き込み、成功時に手順8を再生成が必要な状態にする。Play 終了後にその理由と次の操作を示す。未保存の作業値は終了時に破棄する。

## 3. テスト

Unity の画面に依存しない計算と、設定を書く処理を EditMode で確かめる。画面の描画と操作のテストは書かない。

| 種類 | 何を保証するか |
|---|---|
| EditMode（TDD） | 名前の表：画面に出す設定の項目がすべて表にあり、置く手順が 1 つに決まり、日本語の名前が空でない。ネイティブでは変数名を返す。表にない項目は、どちらでも変数名を返す。繰り返しのグループの要素は、日本語で「砲塔 1・砲身」、ネイティブで `turrets[0].barrel` になる |
| EditMode（TDD） | 変更の数：新しい設定はどの手順も 0。数値を変えると、その手順の数だけが増える。既定に戻すと 0 になり、参照と配置は変わらない。駆動方式で出し分ける手順では、表示している方式の項目だけを数えて戻す |
| EditMode（TDD） | 候補：テストのモデルで、輪の候補が左右に分かれて前から順に並ぶ。もう入っている部位とメッシュのない部位は出ない。転輪と回すだけの輪が名前で分かれる。砲塔のグループで、ほかの要素に入っている部位は出ない |
| EditMode | 結び直し：同じ階層の別モデルに替えると、全部の参照が見つかる。名前を変えた部位は見つからない。結び直しは見つかった参照だけを書き、Undo 1 回で戻る。数値は変わらない。砲塔のグループの各要素と装甲の要素の部位も結び直す |
| EditMode | Play の対象：生成 Prefab のインスタンスは入る。別の Prefab のインスタンスと、Prefab でない物は入らない。出し直した車両として渡したものは入る |
| EditMode | 検証の割り当て：診断の項目名から行と手順が決まる。項目名が空なら全体の扱いになる |
| EditMode | 手順1の固定欄：空の設定を開くだけでは0組。最初の砲塔を明示指定すると1組になり、砲身・任意の砲口は同じ組に書く。既存の1組を開き直しても増えない。2組ある設定を開いても件数・順序・参照が保たれる |

- 共通処理と画面に依存しない判定の EditMode 確認には、非表示診断の行先、同名兄弟と札の位置保持、現在の生成入力・出力が一致する場合と不明な場合、作業値での検証、再適用・再編集後の保存差分、同名の対象の識別・出し直し後の追従、識別子と階層パスの往復を含める。画面上の移動・折り返し・描画は第5節で人が確かめる。

- 除外・未確認：画面の見た目と操作、シーンビューの描画は自動で確かめられないので、5 節で人が確かめる。
