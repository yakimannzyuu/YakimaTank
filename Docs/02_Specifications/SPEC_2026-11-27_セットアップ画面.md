## 1. 内容

各節の見出しの「論点」は、承認の行の番号と選んだ案を指す。選んだ内容は、各節に書いた。

### 1.1 全体の形（論点 1B）

| 場所 | 中身 |
|---|---|
| 上の帯 | 設定アセット（選ぶ・新しく作る）、表示の言語（1.3）、設定の版 |
| 左 | 手順（1.2）。押すと右の中身が替わる。手順ごとに印を出す |
| 右 | 選んだ手順の中身。縦に流す |
| 下の帯 | 検証の件数と状態の文、「生成」「今のシーンに配置・更新」 |

- 設定アセットを選んでいないときは、今と同じく、設定アセットの欄と「新しく作る」だけを出す。
- ウィンドウの幅が狭いときは、左の手順を上のポップアップに畳む（幅は 6.1）。
- 最後に開いていた手順を、ウィンドウが覚える（覚える所は 6.2）。
- Error があるときは「生成」を押せなくし、理由を下の帯の状態の文に出す（更新案の理由：IMGUI では、押せないボタンのツールチップが安定して出ない）。生成の処理は今までどおり、自分でも検証してから作る。

| 調整 | 2 走行・足回り | 走行 9 項目、足回り 7 項目。駆動方式で出し分ける（1.10。0.7.0 は WheelCollider の項目だけ） | 走行は Play 中に再適用、足回りは生成 |
| 調整 | 3 乗降・操作 | 座席 1 項目、VR の操作 5 項目。座席の乗員ロールの欄の置き場（1.10） | Play 中に再適用 |

| 調整 | 5 HP・復活 | 最大 HP・1 発のダメージ・復活までの時間 | Play 中に再適用 |
| 調整 | 6 音・見た目 | 演出の項目のうち、部位の参照を除く 21 項目（基本演出 SPEC 第 2 節）。小見出しは輪・履帯・エンジン音・発射・着弾・破壊 | 数値は Play 中に再適用、参照は生成 |
| 詳細 | 7 同期・接触 | 同期 2 項目、接触 3 項目 | Play 中に再適用 |
| 詳細 | 装甲（0.7.0 では出さない） | 部位・面ごとの装甲の値の一覧と、シーンビューでの色分け（1.10） | — |
| 仕上げ | 8 生成と配置 | 出力先、検証の一覧、前回の生成の結果、今のシーンの配置、シーンの車両の一覧 | — |

- モデルに依存する参照は、すべて手順 1 に置く。装甲の部位だけは、手順「装甲」を出すときに、そこに置く。演出の 25 項目のうち手順 1 に置くのは `leftExtraWheels`・`rightExtraWheels`・`leftTrackTarget`・`rightTrackTarget` の 4 つ。#10 の砲口の位置は、砲塔のグループの要素（`muzzle`）に置く。
- 装甲の手順は、出すときに同期・接触と生成と配置の間に置き、番号を振り直す。
- 演出の項目の行は、基本演出 SPEC の T2 で項目ができた後に、#14 の T5 で手順 1・6 に足す。それまで手順 6 は「0.7.0 の演出で入ります」と出す。
- 砲塔のグループは、基本演出 SPEC の T2b で砲塔のリストができてから作る。画面の作り直しを T2b の後にすると、一度で作れる。それより前に作り直すときは、今の `turret`・`barrel` を 1 組だけ出す。
- 手順の印：
  - Error・Warning があれば、その数を出す（Error を優先）。
  - 必須と仕上げの手順は、なければ ✓ を出す。
  - 調整と詳細の手順は、なければ「既定」か「変更 n」を出す。n は、その手順の数値のうち、新しく作った設定アセットの値と違うものの数（参照は数えない）。駆動方式で出し分ける手順では、表示している方式の項目だけを数える。
- 調整と詳細の手順には「この区分を既定に戻す」を置く。数値だけを戻し、参照と配置は変えない。Undo で戻せる。駆動方式で出し分ける手順では、表示している方式の項目だけを戻す。
- 既定から変えた数値の行は、左に青い線を引き、既定の値を横に小さく出す（Prefab の上書きと同じ見せ方）。

### 1.3 項目の名前と表示の言語（論点 6B と追加の決定）

項目の名前を、上の帯の「表示」で切り替える。

| 表示 | 項目の名前 | 説明（ツールチップ） |
|---|---|---|
| 日本語（既定） | 日本語の名前と単位。例：質量（kg）。決まった用語（Prefab・WheelCollider・Udon・VR など）は訳さない | 日本語の説明。最後に変数名（例：`mass`） |
| ネイティブ | 設定アセットの変数名そのまま。例：`mass`。AI の連携（`YakimaTankSettingsWriter`）・設定アセットのファイル・README の表で使う名前と同じ | 日本語の名前と説明 |

- 手順・見出し・ボタン・メッセージは、どちらの表示でも日本語のまま（6.1）。メッセージの頭に付ける項目名だけは、表示に合わせる。
- 表示の言語は、その PC の Unity の設定（EditorPrefs）に覚え、設定アセットにも Git にも入れない（6.1）。
- 名前・単位・置く手順は、1 か所の表（`YakimaTankFieldLabels`。名前は案）に持つ。表にない項目は、どちらの表示でも変数名を出す。
- 繰り返しのグループ（砲塔・装甲の要素）の項目名は、グループの見出しと要素の中の名前で組み立てる。日本語は「砲塔 1・砲身」（番号は 1 から）、ネイティブは `turrets[0].barrel`（番号は 0 から。AI の連携が要素を指す名前と同じ）。
- 見出しは画面が 1 回だけ描き、設定クラスの `[Header]` は画面に出さない。設定アセットの Inspector は今のまま。

### 1.4 部位の選び方（論点 3C）

- 部位の欄を押すと、検索できる階層の一覧（AdvancedDropdown）を出す。
  - 名前の一部で絞る（大文字と小文字を区別しない）。
  - 各行に、階層パス・メッシュの有無・左右（向きの補正を掛けたモデルの座標で、x の符号。中央付近は「中央」。幅は 6.2）を出す。
  - いちばん上に「候補」の組を出す。
- 候補は `YakimaTankModelInspector` が名前から出すもの（車体・砲塔・砲身・輪）。輪は、転輪と回すだけの輪を名前で分け（6.2）、左右に分ける。もう入っている部位とメッシュのない部位は出さない。
- 配列の欄（左右の転輪・回すだけの輪）は、入っている部位を札で並べ、× で外す。「＋」で一覧を出す。一覧の下に「候補から左に n 個入れる」を置き、まだ入っていない候補を前から順に足す。
- 砲塔のグループでは、要素ごとに候補を出す。ほかの要素に入っている部位も、候補に出さない。
- 候補は押したときだけ入る（0.1.0 で決めた「対応を自動で推測しない」を続ける）。
- 候補の決め方（名前の分け方・「中央」の幅）は 6.2 の始めの値で作り、やきまがローカルの参考モデルで確かめて決める。公開するコードとテストには、参考モデル固有の名前や値を書かず、どのモデルにも通じる決まりとして書く。

### 1.5 シーンビューに描く（論点 4B）

- 手順 1 の切り替えがオンで、開いているシーンにこの設定の生成 Prefab の車両があるとき、その車両の上に描く。手順 1 に描いている車両の名前を出し、候補が複数あるときは選べるようにする。既定は配置の車両で、なければ最初に見つかった車両。
- 描くもの：

| もの | 描き方 |
|---|---|
| 選んでいる部位（手順 1 で今の行、またはマウスを乗せた行） | 範囲の箱（橙） |
| 転輪 | WheelCollider の円（緑） |
| 回すだけの輪 | 点線の円 |
| 輪の前進で回る向き | 矢印。輪を回す設定・軸・反転から求める（演出の項目ができてから） |
| 砲口・座席・車体のコライダー | 点（赤）・点（黄）・細い線 |

- 部位は、設定の参照から階層パスを求め、車両の `Model` の下で同じパスを探して描く。見つからない部位（生成の後に変えた部位など）は描かず、「生成し直すと描きます」と出す。
- 車両がないときは、手順 1 に「生成して置くと、シーンビューに描きます」と出す。
- Play 中も描く（輪の向きを確かめながら調整するため）。描くだけで、シーンは変えない。
- 切り替えの状態は EditorPrefs に覚える。既定はオン。

### 1.6 検証の出し方（論点 5B）

- 次のときに検証し直す。画面を描くたびには流さない。
  - 値を変えたとき
  - Undo・Redo のとき
  - 設定アセットを選び直したとき
  - ウィンドウが前に出たとき
  - 設定アセットが外から変わったとき（AI の連携が書いたときなど）
- 結果は、診断の項目名（`SetupDiagnostic.Field`）から行を決め、その行のすぐ下に出す。配列の項目は、その配列の行の下に出す。項目名が空の結果は、手順 8 の一覧の先頭に出す。
- 手順の印と、下の帯の件数にも出す。手順 8 の一覧の各行から、その手順のその行へ飛べる。
- 「検証」のボタンはなくす。

### 1.7 モデルの差し替え（論点 7B）

- 部位の参照のうち、今のモデルの中を指していないものを見つけたら、手順 1 の先頭に「確かめる項目」を出す。モデルを替えたときも、ほかから設定が変わったときも、同じ見つけ方をする。
- 各参照について、元のアセットの中の階層パスを求め、新しいモデルで同じパスを探す（`YakimaTankModelPaths`）。見つかった・見つからないを並べる。
- 「見つかった n 項目を結び直す」を押すと、見つかった参照だけをまとめて書く。Undo 1 回で戻せる。
- 見つからない参照は、消さずに赤のまま残す（今のような、何も言わずに「なし」に戻すことはしない）。残っている間は、検証が Error で生成を止める。
- 履帯のクリップのパス（`Model/…`）が新しいモデルで解けないときは Warning を出す（演出の項目ができてから）。
- 砲塔のグループの各要素と、装甲の要素の部位も、同じ決まりで結び直す。
- 数値は変えない。

### 1.8 Play 中の画面（論点 8B）

- Play に入ったら、右の中身を「Play で調整」の画面に替える。手順の中身は読むだけにする。
- 「Play で調整」の画面：
  - 対象の車両：この設定の生成 Prefab のインスタンスと、この Play の間にこの画面で出し直した車両だけを出す。手で置いた車両も、生成 Prefab のインスタンスなら入る。台数を出す。
  - Play 中に再適用できる数値を、手順の組ごとに並べる。設定と違う値の行は青い線を引き、設定の値を横に出す。
  - 「再適用」「出し直し」「設定に保存（n 項目）」。保存は、変えた項目の一覧（名前・設定の値 → 作業値）を画面の中で見せてから書く。
- 作業値は今までどおり、Play を抜けると捨て、保存したときだけ設定に書く（ADR 0008）。
- これで `Docs/04_Development/TODO.md` の「Play 中の調整の対象を絞る」は片付く。

### 1.9 作り方（論点 9A）

- IMGUI のまま、ウィンドウを手順ごとの部品に分ける。名前は案。

| 部品（案） | 受け持つこと |
|---|---|
| `YakimaTankSetupWindow` | 枠（上の帯・手順・下の帯）、検証し直す時機 |
| 手順ごとの描画 | 各手順の行 |
| `YakimaTankFieldLabels` | 名前・単位・置く手順・表示の言語 |
| `YakimaTankSettingsDefaults` | 変更の数・既定に戻す |
| `YakimaTankPartPicker` | 検索できる階層の一覧 |
| `YakimaTankPartCandidates` | 候補と左右（Unity の画面に依存しない計算） |
| `YakimaTankModelRebind` | 結び直しの計画と書き込み |
| `YakimaTankSetupSceneView` | シーンビューへの描画 |
| `YakimaTankPlayTargets` | Play 中の対象の車両の絞り込み |

- 画面は、共通の検証・生成・配置・車両の一覧・Play 中の調整を呼ぶだけで、別の手順を持たない。

### 1.10 車両構成の口（#22 の設計への反映）

Issue #22 の想定（複数砲塔・砲塔なし・多人数の搭乗・装甲・駆動方式の選択）に向けて、画面の置き場と決まりだけを先に決める。設定の形は、基本演出 SPEC 第 2 節の「車両構成の口」。使えるようにする実装は #22 の子 Issue で行う。

| 口 | 画面での扱い | 0.7.0 |
|---|---|---|
| 砲塔のリスト | 手順 1 の繰り返しのグループ。要素は「砲塔・砲身・砲口（任意）」の組で、足す・外す・並べ替えができる。要素 0 個（砲塔なし）も設定としては入れられる | 出す。検証は要素 1 個だけを求め、ほかは「プロトタイプ以降」の Error |
| 駆動方式 | 手順 2 の先頭で選び、項目を方式で出し分ける。履帯直接制御の項目（左右の履帯の推力・接地・輪ごとのサスペンション）は #22 の子 Issue で決める | 選ぶ欄を出さない。WheelCollider の項目だけを出す |
| 座席の乗員ロール | 手順 3 で、座席に持たせるロール（操縦・砲手・車長・装填手）を選ぶ。ロールが持つ操作は、操作の項目ではなくロールの定義で表す。複数砲塔での砲手と砲塔の対応も、ここに置く（決め方は #22） | 6.2 |
| 装甲 | 詳細の組の手順「装甲」。部位・面ごとの値の一覧と、シーンビューでの色分け | 出さない |

- 画面に出さない口も、設定には既定値で入り、検証と結び直しの対象になる。

## 3. テスト

Unity の画面に依存しない計算と、設定を書く処理を EditMode で確かめる。画面の描画と操作のテストは書かない。

| 種類 | 何を保証するか |
|---|---|
| EditMode（TDD） | 名前の表：画面に出す設定の項目がすべて表にあり、置く手順が 1 つに決まり、日本語の名前が空でない。ネイティブでは変数名を返す。表にない項目は、どちらでも変数名を返す。繰り返しのグループの要素は、日本語で「砲塔 1・砲身」、ネイティブで `turrets[0].barrel` になる |
| EditMode（TDD） | 変更の数：新しい設定はどの手順も 0。数値を変えると、その手順の数だけが増える。既定に戻すと 0 になり、参照と配置は変わらない。駆動方式で出し分ける手順では、表示している方式の項目だけを数えて戻す |
| EditMode（TDD） | 候補：テストのモデルで、輪の候補が左右に分かれて前から順に並ぶ。もう入っている部位とメッシュのない部位は出ない。転輪と回すだけの輪が名前で分かれる。砲塔のグループで、ほかの要素に入っている部位は出ない |
| EditMode | 結び直し：同じ階層の別モデルに替えると、全部の参照が見つかる。名前を変えた部位は見つからない。結び直しは見つかった参照だけを書き、Undo 1 回で戻る。数値は変わらない。砲塔のグループの各要素と装甲の要素の部位も結び直す |
| EditMode | Play の対象：生成 Prefab のインスタンスは入る。別の Prefab のインスタンスと、Prefab でない物は入らない。出し直した車両として渡したものは入る |
| EditMode | 検証の割り当て：診断の項目名から行と手順が決まる。項目名が空なら全体の扱いになる |

- PR までに通す検証：C# と UdonSharp のコンパイル、EditMode と PlayMode の全部（Runtime を変えないことの確かめを含む）、生成、開発ワールドの更新。最終の入力に対応する要求 ID と結果を残す。
- 除外・未確認：画面の見た目と操作、シーンビューの描画は自動で確かめられないので、5 節で人が確かめる。
