## 1. 内容

演出（履帯・転輪・エンジンの音）を各クライアントで出すための、表示用の速度と角速度を返す入口を、車体の同期に足す。4 台での通信量と重さを測る手順を用意する。測った結果で、送る間隔の既定値を決める。

### 1.1 表示用の速度・角速度を返す入口

- 車体の同期の Udon（`YakimaTankVehicleSync`）に、表示用の速度と角速度（ワールドの向き、m/s・rad/s）を返す入口を足す。UdonSharp は `out` の引数を使えないので、速度と角速度で 2 つに分ける。
- 返す値：
  - オーナー：Rigidbody の速度と角速度。
  - オーナー以外：最新の受けた状態の速度と角速度（ユーザーが決めた）。表示している姿勢より、送る間隔の 2 倍ほど先の値になる。ただし、最新の状態が止まった印のとき、表示の時刻が最新の状態の時刻を先読みの上限より過ぎたとき（表示も止まっているため）、状態をまだ受けていないときは 0。
- 同期変数を足さない。アクセルの量は送らない（エンジンの音は、速さとその変化から各クライアントで推定する）。
- 発射は発射の番号から、破壊は生存の状態から出す（0.5.0・0.6.0 で済み）。
- 計算は静的な関数に分け、EditMode で確かめる。

### 1.2 1 回の大きさを見る

- 送った状態の大きさは、VRChat が `OnPostSerialization` の結果（`SerializationResult.byteCount`）で知らせる。ClientSim の値は、項目の数から作った仮の値で、実際の大きさではない。
- 車体・武器・生存の状態の同期の Udon が、最後に送れた大きさを覚える（送れなかったときは変えない）。デバッグ UI のオーナーの欄に、`Bytes 車体/武器/生存` の形で出す（ユーザーが決めた）。まだ送っていなければ 0、部品がなければ `-`。

### 1.3 4 台での通信量と重さを測る手順

人が VRChat で測る。測ったら、結果を下の表の形で TASKS に書き、送る間隔の既定値を決めて、ADR 0009 の未決事項「Manual 同期の送信条件と間隔」に注を足す。

| 測るもの | 見る所 | 場面 |
|---|---|---|
| 送った回数（Sent/s）と、送る要求の回数（Req/s） | デバッグ UI（各車両のオーナーの画面） | 4 台が走りながら狙う・止まる・撃ち合う |
| 1 回の大きさ | デバッグ UI の `Bytes`（1.2） | 同上 |
| 重さ | VRChat の画面の FPS（VRChat の表示か、外部の FPS の表示）と、Unity の Profiler（ユーザーが決めた） | 車両 0 台と 4 台、自分が乗っているときと乗っていないとき |

手順の案：

1. 車両を 4 台置いたワールドをアップロードする（ユーザー）。それぞれの車両にデバッグ UI を 1 枚付ける。
2. 4 つのクライアント（できれば別の PC・回線）で入り、1 人 1 台に乗る。
3. 次の場面を、それぞれ 1 分ほど続け、各自の画面の Sent/s・Req/s・Bytes と FPS を書き留める：車両がない（または誰も乗らずに止まっている）、4 台が走りながら砲塔を回す、撃ち合う（破壊と復活を含む）。
4. 送る間隔（既定 0.1 秒）を 0.15・0.2 秒にした設定でも、見え方（ほかの人の車両の滑らかさ）と回数を比べる（Play 中の調整では VRChat に持ち込めないので、設定を直して生成し直し、アップロードし直す）。
5. 各車両の重さの内訳は、Unity の Play（ClientSim）で 4 台を置き、Profiler（CPU の Udon の項目）で 1 台あたりの時間を見る。自分の車両（オーナー：物理と接触の計算）と、ほかの人の車両（補間）で分けて見たいときは、3 台をテスト用のほかのプレイヤーの持ち物にする（ClientSim のほかのプレイヤーを足して所有権を渡す）。
6. 結果と見え方から、送る間隔の既定値を決める。

### 1.4 例外の扱い

| 起きること | 扱い |
|---|---|
| 状態をまだ受けていない（途中参加の直後） | 0 を返す |
| オーナーが代わった直後 | 新しいオーナーは Rigidbody の値、ほかの人は履歴を作り直すまで 0（0.3.0 の履歴の作り直しのとおり） |
| 破壊の間 | 車体は停止中のブレーキで止まるので、値もほぼ 0 |

### やらないこと（この版）

- 音・転輪・履帯・閃光・破壊の見た目（別に相談する）
- アクセルの量の同期、演出のための同期変数
- 遅れを人工的に入れる自動テスト

## 3. テスト

| 種類 | 何を保証するか |
|---|---|
| EditMode（TDD） | 表示用の速度・角速度の計算：最新の状態の値、止まった印、表示の時刻が先読みの上限を過ぎた、状態がない。デバッグ UI の `Bytes` の文字 |
| PlayMode（ClientSim・Udon VM） | オーナーは Rigidbody の値を返す。オーナー以外は、最新の受けた状態の値を返し、止まった印の状態では 0。車体・武器・生存の状態の同期が送った大きさを覚える。0.1.0〜0.6.0 の PlayMode が通る |
| 開発環境 | 開発用のモデルで上の PlayMode。開発ワールドの更新を 2 回。ローカルビルド |
