## 1. 内容

0.2.0 の実装のレビューで見つかった 3 つの不具合を直す。1.1 は 0.1.0 からある不具合。

### 1.1 車体の範囲から砲塔・砲身を除く

今の実装では、車体自身にメッシュがない（メッシュを持たない親を車体に選んだ）とき、車体の下のすべてのメッシュから範囲を求める。親の下に車体のメッシュと砲塔・砲身があるモデルでは、車体のコライダー（`Colliders/Body`）が砲身の先まで張り出し、車体が壁に届く前にぶつかる。座席の自動の位置（0.2.0 の 1.1）も同じ求め方で、砲塔自身にメッシュがないと、砲身の分だけ前へずれる。

- 車体のコライダーの範囲：
  - 車体自身にメッシュがあれば、そのメッシュだけ（今までどおり）。
  - なければ、車体の下のメッシュから求める。そのとき、対応の砲塔と砲身の階層（子孫を含む）を除く。転輪は除かない（底は今までどおり転輪の中心で切る）。
- 座席の自動の位置：砲塔自身にメッシュがなければ、砲塔の下のメッシュから求める。そのとき、対応の砲身の階層を除く。除いた後にメッシュがなければ、今までどおり砲塔の原点。
- 検証：車体自身にメッシュがなく、砲塔・砲身を除くと車体の下にメッシュがないときは、生成の前に Error にする。「車体の範囲を求められません。砲塔と砲身を除くと、車体の下にメッシュがありません。車体には、車体のメッシュがある階層を選んでください。」
  - 今は検証を通って、生成の途中で失敗する。

### 1.2 出し直しでデバッグ UI をつなぎ直す

Play 中の出し直し（0.1.0 の 1.5）は、前の車両を消して新しい車両を作る。前の車両を表示していたデバッグ UI（車両とは別の Prefab）は参照を失い、付いて行くのも操作値の表示も止まる。

- 共通の出し直しの処理（`YakimaTankPlayTuning.Respawn`）で、前の車両を消す前に、読み込んでいるシーンから前の車両を表示しているパネルを探す。
- 新しい車両に値を書いて適用した後で、そのパネルの表示する車両を新しい車両にする。変えるのは実行中の Udon の値だけで、シーンのファイルは変えない（Play を抜けると戻る）。
- パネルの位置・付いて行くかの設定・付いて行くときの位置と向きは変えない。
- 別の車両を表示しているパネルは変えない。前の車両の中に置いたパネルは、車両と一緒に消える。

### 1.3 PlayMode の時間を物理の秒で数える

走行の PlayMode のテストは、物理の更新を毎秒 50 回と決めて回数で待っている。ClientSim を始めると、刻み幅が ClientSim の設定（既定で毎秒 90 回）に変わるので、乗車を含むテストでは秒の条件が短くなる。たとえば「降りてから 5 秒以内に止まる」を約 2.8 秒で判定している。また、ClientSim は変えた刻み幅を戻さないので、後に流れるテストの刻み幅も変わる。

- テストの秒の条件（待つ時間・期限・測る区間）を、経過した物理の時間（`Time.fixedTime` の差）で数える。
- 判定の数値（秒・距離・速さ・角度）は変えない（0.1.0 と 0.2.0 の 3 節のまま）。
- 刻み幅（`Time.fixedDeltaTime`）と目標のフレームレート（`Application.targetFrameRate`）を、テストの前に覚え、後処理で戻す。
- 製品のコードは変えない（テストの基底だけ）。

### やらないこと

- 乗車の判定（モデル全体の範囲）と、転輪の範囲の求め方は変えない。
- 砲塔・砲身の対応がないモデルで、車体の下の砲身を見分けること（対応がなければ除けない）。
- ClientSim の刻み幅の設定を変えること。

## 3. テスト

| 種類 | 何を保証するか |
|---|---|
| EditMode（TDD） | 生成：車体自身にメッシュがなく、子に車体のメッシュと、前へ長く突き出す砲身を持つ砲塔があるモデルで、車体のコライダーの前端が車体のメッシュの範囲に収まる。車体自身にメッシュがあるモデル（今のテスト用のモデル）では、車体のコライダーが今までと同じ。砲塔自身にメッシュがなく、子に砲塔のメッシュと砲身があるモデルで、座席の自動の位置の前後左右が砲塔のメッシュの中央。検証：砲塔・砲身を除くと車体の下にメッシュがないとき Error |
| PlayMode（TDD） | 出し直し：前の車両を表示しているパネルが、出し直した車両を表示し、その車両に付いて行き、その車両の共通操作値がゲージに出る。パネルの付いて行く設定と位置・向きの値は変わらない。時間：物理の秒で待つと、刻み幅が毎秒 50 回でも 90 回でも、指定した秒数だけ物理が進む。ClientSim で変わった刻み幅と目標のフレームレートが、後処理で元に戻る |
| 開発環境 | 開発用のモデルの最終の生成 Prefab で上の PlayMode。開発用のモデルの生成（車体のコライダーが変わるかを記録する） |

- 不具合は、再現するテストが失敗することを確かめてから直す（rules 6 章）。
- PR までに通す検証：C#・UdonSharp のコンパイル、生成、EditMode・PlayMode、開発ワールドの更新、ローカルビルド。最終の入力に対応する要求 ID と結果を残す。
- 除外・未確認：VRChat での壁との当たりの見た目は、人が確かめる（5 節）。
