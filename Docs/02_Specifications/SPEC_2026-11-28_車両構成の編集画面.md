# 車両構成を編集するセットアップ画面（#22 設計案）

- 2026-11-28、やきまが将来の詳細を #22 側に置く方針を承認した。本書は子 SPEC に取り込むための設計案。
- 対象はプロトタイプ以降。各機能は担当の子 Issue で設定の保存形式・共通検証・生成への適用を承認した段階で有効にする。
- 0.7.0 で利用できるのは、砲塔1組、WheelCollider、1座席で操縦と砲手を兼ねる構成、一律ダメージ。画面から指定する砲塔・砲身・任意の砲口は手順1に置く。以下の編集操作を 0.7.0 に表示する対象には含めない。
- Unity 2022.3 の IMGUI を使う。画面は利用者が指定した対象と操作を共通の Editor 処理に渡し、返された値・診断・結び直し候補を表示する。モデルや実行中の車両を画面から直接書き換えない。構造の編集は Edit 中に行い、Play 中は読み取り専用とする。元モデルを変更せず、反映は同じ出力 Prefab の再生成を通す。
- 本書の `turrets`・`driveType`・`seatRoles`・`armorZones` は版7で予定している設定名。新しい関数名や、座席配列・砲手対応の保存キーは規定しない。

## 1. 手順1　砲塔・砲身・砲口

1. 砲塔を設定順に並べ、各見出しに1始まりの番号と、割り当てた砲塔のモデル内パスを表示する。展開した組に砲塔・砲身・任意の砲口を置く。追加は末尾に空の1組を作り、最初の欄に移る。表示・展開・検索だけでは設定を書かない。
2. 部位ピッカーは操作した要素と欄を保持する。砲身はその砲塔の子孫、明示する砲口はその砲身の子孫から選ぶ。候補と全階層を区別し、他の砲塔グループで使用中の部位は候補から外す。範囲外や既使用の部位には理由を示す。砲塔や砲身を変更して既存の子参照が外れたら、元の指定を残して該当行で修正を求める。任意の砲口を明示的に空にした場合は既存の砲口解決順を使う。
3. 上下移動は組全体を移す。開いている組、選択行、診断、砲手席の対応を同じ砲塔に追従させる。削除前に影響する座席を示し、付け替え・明示的な解除・取り消しを選べるようにする。削除と付け替えは1回の編集として確定し、Undo 1回で対応も戻す。削除後に同じ番号へ繰り上がった砲塔へ引き継がない。
4. 最後の1組も削除できる。要素数0を「砲塔なし」と表示し、追加操作を残す。1組の参照が空の状態は「未設定」であり、0組と区別する。旧単数フィールドから移行したアセットでも、最後の1組を明示削除して保存した後の再読込で砲塔が復活しないことを受入条件とする。これは移行不成立で旧参照を保持する場合と区別する。固定砲・曲射砲の設定はこの操作から推定しない。0.7.0 の「ちょうど1組」の検証を緩めるのは、担当の子 Issue で対応する構成を生成できるようになった段階とする。
5. モデル差し替え時は、各組の各欄で旧パスと新しい対応先、見つからない理由を確認する。同じパスが見つかっても、新しい砲塔・砲身との親子条件を満たさない参照は一括確定から外す。見つかった参照だけを利用者の操作で確定する。未解決の行から同じ欄を選び直せる。結び直しでグループ順、砲手対応、武器の共通値を変えない。
6. ラベル表にはグループ名と要素内の項目名を登録する。日本語は「砲塔 2・砲身」、ネイティブは `turrets[1].barrel`。行・診断・部位ピッカーで同じ対象を示す。並び替えでは現在の添字からラベルを引き直す。席からの対応を表示名や添字だけで復元しない。

**受入例**　A・B の2組で B を担当する席を作り、B を先頭へ移す。診断の添字は変わり、担当は B のまま。B の削除を取り消すと配列と対応は元のまま。削除を確定して Undo すると両方が戻る。モデルを替えて B の砲身だけ階層名が変わった場合、B の砲身だけを選び直せる。

## 2. 手順2　駆動方式と足回り

- 手順2の先頭で `driveType` を選ぶ。直下には、共通の走行値と選んだ方式に属する値を表示する。WheelCollider を選ぶと現行の足回りを表示する。履帯直接制御を選ぶと、同方式の子 Issue で承認された欄を表示する。未実装の段階では選択操作を公開しない。
- 切り替えは1回の Undo 対象とする。各方式で入力済みの値を保持し、元の方式へ戻したら前の値を再表示する。すでに入力した値を他方式の単位に換算したり、既定値で上書きしたりしない。方式変更は再生成で反映する。
- 「変更 n」は手順2に現在表示している数値のうち、新規設定の同じ方式の既定値と異なる項目数。共通値は表示されていれば1回だけ数える。「この区分を既定に戻す」も同じ範囲に適用する。方式の選択、参照、非表示の値、配置は保持する。
- 生成に関する数値診断は使用中の方式に属する欄に表示する。非表示の方式固有値は現方式の生成条件に含めない。方式そのものが使用できない場合は、方式選択の行に理由を返す。

**受入例**　WheelCollider の値を1項目変更し、履帯直接制御へ切り替える。その1件は表示中の変更数に入らない。切替先で既定に戻してから WheelCollider に戻ると元の変更1件が残る。

## 3. 手順3　座席の乗員ロールと担当砲塔

- 複数座席の保存と生成を有効にした段階で、設定上の座席ごとに見出しを置く。見出しに座席番号と座席位置（部位を割り当てた場合はそのパス）を表示し、展開すると操縦・砲手・車長・装填手の割り当てと、その座席の担当砲塔を確認できる。既存の単座設定を開くと、同じ座席に既存のロールが表示される。画面を開いただけでは座席も担当砲塔も増えない。
- 砲手ロールのある座席には担当先の選択欄を出す。候補に手順1の砲塔番号と部位パスを併記し、選んだ座席と砲塔の組を確認して確定する。同じ名前の砲塔も判別できるようにする。許される担当数・共有可否は、照準方式の子 SPEC が定める条件に従う。
- 砲手ロールを外す、座席を削除する、担当砲塔を削除する場合は、影響を受ける対応を変更前に表示する。利用者が解除または付け替えを確定したときだけ、ロール・座席と対応を一緒に書く。取り消し・Undo・保存後の再読込で同じ組を復元できること。砲塔0組のときは選択候補0件と示す。
- 設定上の担当と Play 中の着席状態は別に表示する。未着席による代行、同時照準、入力パネルは本節の対象外。複数座席・対応関係の保存形式が決まるまでは編集を有効にしない。座席ごとのネイティブ名は実際に採用した保存形式から表示する。

**受入例**　2席・2砲塔で、席を並べ替えて保存し直しても担当砲塔が入れ替わらない。片方の席で砲手を外す操作を取り消した場合、元のロールと対応が両方残る。

## 4. 手順8　装甲の一覧とシーン描画

- 1行を `armorZones` の1要素とし、モデル内の部位 `part`、面 `face`、値 `value` を横に並べる。面は前・横・後ろ・上・下の5種類。「横」は左右両側で1件。日本語は「装甲 1・部位」、ネイティブは `armorZones[0].part` の形とする。狭幅で折り返しても、行と診断の対応を保つ。
- 追加は部位・面・値を選んで確定する。下書きを取り消したら要素は増えない。既存行から変更・削除でき、1操作を Undo 1回で戻す。同じ部位・同じ面の重複は両方の行を示し、後の行で前の値を上書きしない。別の面は同じ部位に設定できる。0件は装甲指定なし。無効な部位参照は元の行に残し、1.7 の手順で再指定する。値の単位・許容範囲は装甲の子 SPEC に従う。
- 装甲手順では、1.5 で選んだ車両と描画オン／オフを共有する。選んだ部位の範囲に、設定した面を示す。表示上の前・上は向き補正後の車両の初期姿勢（前 +Z、上 +Y）を基準とし、砲塔などの可動部ではその面を部位の動きに追従させる。被弾面の判定は装甲の子 SPEC で扱う。表示中の有効な値の最小・最大を凡例に記す。同じ数値は同じ色、未設定は塗らず、選択行は輪郭と部位名・面・値でも識別する。値がすべて同じときは1色とその値を示す。色は入力値の比較用であり、被弾時の効果を表さない。
- 一覧の行を選ぶと該当する面を強調する。「横」は左右を一緒に強調する。部位が生成車両に見つからない場合はその行に理由を示し、別部位を代わりに描かない。描画は読み取り専用とし、モデルのマテリアル・Collider・シーンの保存状態を変えない。装甲手順の公開前は、0.7.0 の装甲要素に対する Warning を維持する。

**受入例**　同じ車体に前と横を登録し、前の行を選んで表示部位と数値を確認する。前をもう1件登録しようとすると競合の2行を特定できる。描画を切っても設定は残り、モデル差し替えで失われた部位は別の面に描画されない。
